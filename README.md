# itenev23.github.io

Personal portfolio of Ivaylo Tenev, Senior Software Engineer. Live at https://itenev23.github.io

Vite 8 · React 19 · TypeScript · TanStack Router · Tailwind 4 · React Three Fiber · React Flow

**What's in it:**
- The home page is one scroll-driven "work line" through every project.
- Each project has an explorable architecture board (3D and 2D), case studies written like
  decision records, and an evidence graph that links skills to the work that proves them.
- Matrix-green theme.

See [docs/README.md](docs/README.md) for everything that's built and what's next.

## Develop

Requires **Node ≥ 22.12** (see `.nvmrc`) and **pnpm**.

```sh
pnpm install
pnpm dev        # http://localhost:5173
```

| Command | What it does |
| --- | --- |
| `pnpm dev` | Dev server with hot reload |
| `pnpm verify` | Lint + typecheck + tests + build: exactly what CI runs |
| `pnpm build` then `pnpm preview` | Serve the production build at http://localhost:4173 |
| `pnpm test` | Content and diagram integrity tests, publishing-safety checks |
| `pnpm lint:fix` | Format and auto-fix lint issues (Biome) |

`src/routeTree.gen.ts` is generated by the TanStack Router plugin on `dev`/`build`.
It is committed on purpose; don't edit it by hand.

### The CV PDF

`pnpm build` ends with [`scripts/build-resume.mjs`](scripts/build-resume.mjs), which uses the shared
[`scripts/resume.mjs`](scripts/resume.mjs).
- **What it does:** prints the `/cv` page to `dist/resume.pdf` with headless Chrome, so the
  "Grab my CV" PDF comes from the same content as the site.
- **Format:** A4, selectable text, links to the public site.
- **Chrome:** it uses the Chrome you have installed (`puppeteer-core` downloads no
  browser); set `CHROME_PATH` if it isn't found. Without Chrome the step is skipped with a
  warning locally, and fails in CI.
- **Length:** it prints the page count and warns above two pages.
- **In development:** `pnpm dev` renders the PDF on request (a small plugin in
  `vite.config.ts`, same code as the build), so the download links work there too. It takes
  a second or two, and always reflects the current content.

### Troubleshooting

- **`Cannot find module '@rolldown/binding-…'`** or engine warnings: Node is too old.
  Upgrade Node, delete `node_modules`, then run `pnpm install` again. pnpm skips
  native bindings whose engine range doesn't match the running Node.
- **Port 4173 already in use** after stopping `pnpm preview`: a child process can outlive
  it. Stop whatever listens on the port, then start the preview again.

## Edit content

Everything visitors read lives in [`src/content`](src/content). Schemas are in
[`schema.ts`](src/content/schema.ts). Invalid content fails `pnpm test` and CI.

| To change | Edit |
| --- | --- |
| Name, headline, `tagline` (the joke after the title in the hero), `pitch` (straight, for the CV), `intro` (the hero's winking version), `invite` (the contact section), socials, email, and `notes`: career facts no single project shows (mentoring, unlisted projects, hackathons), shown on the home page and the CV | `profile.ts` |
| Skills (`depth` 1-5 sets emphasis in the evidence graph) | `skills.ts` |
| Projects; `kind` is `work` (main), `side` or `mentoring`. Main projects are full chapters on the home page, side projects and mentoring one row each; `featured: true` gives a flagship the longer CV entry | `projects/<slug>.ts` + register it in `index.ts` |
| A project's public links, footprint numbers and "also delivered" items | its `links`, `footprint`, `delivered` |
| A project's explorable board (hero, 3D and 2D) | its `architecture`, e.g. `projects/auction-saas-architecture.ts` |
| Case studies | `case-studies/<slug>.ts` (with `project: "<slug>"`) + register it in `index.ts` |
| "Problem solving" principles (each links a case study) | `principles.ts` |
| What the docked agent says: a greeting per page path, a line per section id, a funny line per project (first visit), quips that take turns after that, and his click replies | `agent.ts` |
| Certifications, certificates, courses and events (`kind`), each linking to the issuer's verification page; a certification's badge image goes in `public/badges/`; a certificate's courses go in `parts` | `credentials.ts` |
| Earlier roles and education, shown without dates on the home page and the CV; a role's `summary` (an education entry's `note`) goes on both, `highlights` only on the home card; a role with `projects` is told by those project chapters on the home page and under the role on the CV, never twice; `cv: false` keeps a role (such as seasonal jobs) off the CV | `career.ts` |

A project's page shows its overview, footprint, highlights, technologies, board, case
studies and `delivered`: work that commit history doesn't show, with a
`shipped · ready · ongoing` status. Projects carry no dates and no "current" flag; credentials show only the year earned.

A case study answers the same questions every time: `context`, `constraints`, `approach`
(what I did), `decisions` (`title` / `why` / `tradeoff`), `outcomes` (`metric` / `value`)
and an optional `retrospective` (incidents owned, what I'd change). `skills` are IDs
from `skills.ts`; they link the case study into the evidence graph.

The optional `architecture` block draws the diagram. The same model drives the hero, the
3D board, the 2D view and every case-study diagram:

- `direction`: `LR` (left → right, case studies) or `TB` (layered, project boards).
- `lanes`: `{ label, y }` bands for layered diagrams; every node must sit on one.
- `zones`: `{ label, from, to, tone }` groups consecutive lanes into one region on the 3D board
  (`primary` · `team` · `external`).
- `nodes`: `x`/`y` are grid units, not pixels. `kind` picks the symbol and icon. `owner` is one of
  `built · contributed · integrated · platform · external` and colours the box: **never
  mark another team's work as `built`**.
- Node details are points, not prose: `features` (what it does), `tech`, `myWork` (my part),
  plus a one-line `note`. `short` is the label used on the dense 3D board; `caseStudy`
  links a box to its case study.
- `edges`: `from`/`to` node IDs; `kind` is `http · event · queue · invoke · ai · data`.
- `flows`: a request walked step by step, each step an existing edge plus a caption.

`pnpm test` fails on:
- a dangling reference;
- a skill nothing proves;
- placeholder copy;
- anything that looks like an internal hostname, ARN, account ID, private IP, env-var or
  queue name, or a ticket ID.

Public product websites (e.g. a product's `www` site) are allowed. The site is public, so
keep labels generic.

## Theme

Colours are design tokens in the `@theme` block of [`src/styles.css`](src/styles.css).
The primary is `--color-matrix` (`#00ff41`), used as `text-matrix`, `bg-matrix`,
`border-matrix/40` and so on. Surfaces are green-black. Accents in content are shades of the same green. Details:
[ARCHITECTURE.md §7](docs/ARCHITECTURE.md#7-theme).

## Deploy

Pushing to `master` runs [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):
verify → build → publish to GitHub Pages. Pull requests run the checks without deploying.

One-time setup: **Settings → Pages → Source: GitHub Actions**.
